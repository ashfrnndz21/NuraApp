## 1. Summary

1. On WebKit — Safari, the only engine on an iPhone — **opening Profile freezes the app within 500 ms**, with
   one network request and a blocked main thread. Chromium is fine. If he tested on a phone, this alone is a
   large part of "this is not coming up to it".
2. The owner is right about the rest. About half the app is the blueprint; the other half is the app that
   existed before it.
3. The engine underneath is not the blueprint's engine at all. It is a deterministic pipeline with single-shot
   model calls bolted on at fixed points, and a regex gate on the far side that deletes the answers.
4. Reproduced his exact complaint, on fixtures: "How is my cholesterol?" → *"Your cholesterol test from Friday
   18 September is in your papers."* No number. "Is it high?" → *"Nura does not have that written down. Ask Dr
   Tan."* About a paper he uploaded and confirmed himself, whose value the app had printed two taps earlier.
5. The cause is structural, not a bug: the fallback catalogue has exactly one template that can state a measured
   value and it is blood-pressure-only, so a cholesterol number has nowhere to live.
6. Nothing checks whose paper it is. Nothing checks whether a paper is a duplicate. I uploaded the same policy
   twice and got two policies; the same panel three times and got three papers, silently.
7. Intake never asks a question. The build plan promises "Nura … asks which statin it is"; the screen shows
   **The medicine: STATIN** with **Looks right** as the primary button.
8. The new person's path to Home is roughly 30 screens, 13 of them a one-question-per-screen settings wizard
   before the bubble cloud the blueprint opens with. **[#318]**
9. Home's Add-a-paper path never reaches "What it means for you" at all — it ends on the batch screen.
10. Packages 12 (visits/costs), 14 (Not well, Connect, Mei's Home, Profile) and 18–22 are untouched, and they are
   exactly the screens that look pre-redesign to him.
11. There is no evaluation of answer quality anywhere in the repo. Every gate is an unmeasured hypothesis.

**Engines — and the biggest single finding in this audit.**

On WebKit, **opening Profile hangs the page.** Reproduced three times, isolated:

- On Home, `document.querySelectorAll("*").length` returns **319 nodes in 7 ms**.
- Tap **Profile**. Within **500 ms** the same one-line `page.evaluate(() => 1)` **never returns** — the
  renderer's main thread is blocked and stays blocked for as long as I waited (149 s in one run).
- Playwright counts requests out of process, so it keeps counting while the page is frozen: **exactly one
  request** was made after the tap. It is **not** a network loop, a retry storm or a slow endpoint. It is a
  synchronous loop in the page's own JavaScript.
- Everything downstream is lost with it: in the full WebKit walk, `55-pa-profile`, `56-pa-emergency`,
  `57-pa-not-well`, `58-pa-not-well-answer` and `46-pa-insurance-empty` were **never captured**, and the walk
  could not click `profile-insurance`. All five captured normally on Chromium.

WebKit is Safari. Safari is the only engine on an iPhone. **On the owner's phone, Profile — and therefore the
emergency card, insurance and the way back out — is a freeze.** I did not bisect to the offending component;
the evidence says look for a synchronous loop mounted by the Profile screen (`web/src/screens/ProfileParts.tsx`
and what it renders), not for a fetch.

Apart from that, the two engines produced the same screens and the same measurements — the same px, the same
weights, the same sub-12.5px offenders. One cosmetic difference: Services renders the time as **"4:41 PM"** on
WebKit and **"4:41 pm"** on Chromium. **I did not diff every WebKit frame against its Chromium twin pixel for
pixel.**

**Errors and blank frames.** No blank frames in either engine. One console error in both engines, on the
first feed card: `Failed to load resource: the server responded with a status of 404`. **Traced, and it is not
a defect:** `GET /profiles/{id}/feed/{item}/voice` returns 404 by design when a card has no prepared audio —
`backend/app/channels/api/feed.py:223-234`, *"404 when there is no audio for this card in that language (no
voice for it yet, too long to say …): the phone then says it with its own voice."* What **is** a defect is why
there was no audio: the server logged `nura.delivery.feed: voice ahead failed … TooLongToSay` **ten times**, so
every card fell back to the phone's own voice rather than Nura's.

**A correction to the brief's own expectation.** The walk asked for ten feed cards. The feed API returned
**five** items for demo Pa, all `format: "text"`, all with `source_id: null` — no clip, no article, no learning
card. My ten captures are ten scroll positions over those five. The live web search has never run on this
backend (build-plan log, package 13), so this is the expected fixture state, not a regression.

## 3. The intelligence layer

### 3.1 Ask drops the fact, and the reason is three failures stacked

Measured, twice, on fixtures, with a confirmed lipid panel on file:

> **"How is my cholesterol?"** → *"Your cholesterol test from Friday 18 September is in your papers."*
> **"Is it high?"** → *"Nura does not have that written down. Ask Dr Tan."*

**(a) The number has no legal home.** The rule-based asker composes from a closed catalogue. The template it
used is `RECALL["en"]["paper"]` — `backend/app/delivery/timeline_strings.py:278`:

```
"paper": "Your {what} from {date} is in your papers."
```

`_compose` (`backend/app/search/ask.py:841-847`) renders a confirmed lab fact through that template and never
touches `fact.value`. The **only** catalogue template in the app that states a measured value is `READING`
(`timeline_strings.py:544-548`), and it is blood-pressure-only. A cholesterol number cannot be said by this
path, ever, by construction.

**(b) When the model path runs, rule 5 kills the sentence and the number rides down with it.** `verify(text,
language, "ask")` at `backend/app/llm/ask_agent.py:1854`. Rule 5 is the **date** rule, not a units rule —
`backend/app/safety/plain_words.py:968` `_check_dates`, patterns at `:312-317`, month-without-weekday at
`:1001-1010`. *"Your cholesterol was 5.4 on 12 March."* fails rule 5 alone — exactly the `rules=[5]` the owner
saw — and the whole line is deleted, number included. Meanwhile `ask_agent.py:716` hands the model the fact
with an **ISO** date:

```python
f"{fact.subject} {fact.attribute} = {fact.value} on {on.isoformat()} ({elapsed})",
```

and the prompt then asks for "Wednesday 21 January". **The pipeline hands the model a string guaranteed to
fail its own gate, then deletes the line for using it.** Rules 12 (`mmol/L`, `mg/dL`, `LDL`, `HDL` —
`plain_words.py:382-384`, `:380`), 10 (more than three numbers — a four-analyte panel cannot be one line,
`:1100-1116`), 3 ("triglycerides" is ≥9 chars and ≥4 syllables, `:1204-1215`) and 1 (*"Total cholesterol
5.4."* is a fragment, `:1154-1186`) close every remaining way to say it.

**(c) "Is it high?" was discarded with no repair round.** The conclusion blocklist is
`backend/app/llm/narrate.py:119-134` — `looks, seems, should, must, high, low, normal, fine, worse, better,
risk, danger, safe` — applied at `ask_agent.py:1870-1872`. Any answer using the questioner's own word dies,
including *"Your papers do not say whether it is high."* and *"Ask Dr Tan whether it is high."* — the gate
blocks the very hand-off the boundary rule demands. And the drop **records no `Finding`**, so the repair round
at `ask_agent.py:1181` (`… and failed_findings and …`) never fires: the model is never told why. The same hole
was recognised and fixed for the unconfirmed-card check (pseudo-rule 91, `:1722-1725`) and not for this one.

**(d) There is no escape hatch for a confirmed fact.** `verify()`'s signature is
`plain_words.py:1388`: `verify(text, language="en", kind="line")`. **Provenance is not an input.** A value the
owner photographed, reviewed and said yes to is held to exactly the same gate as a number the model imagined.
The only provenance-aware check in the pipeline, `_claims_a_value_from_an_unconfirmed_card`
(`ask_agent.py:1791-1805`), exists only to make the gate *stricter*.

**(e) The app contradicts itself.** The onboarding read-back happily prints **"Your cholesterol was 212 on
…"** (captured: `06-23-readBack`). The same number, from the same paper, is unsayable in Ask.

### 3.2 Intake

- **Classification** is one unchecked model call with a closed schema (`backend/app/ingestion/claude_extract.py:374`,
  `_SCHEMA` `:170-189`), one prompt for every kind (`backend/app/llm/prompts/extract_document.txt:7-21`). No
  confidence on the classification itself. A value outside the enum destroys the whole page
  (`claude_extract.py:324` → blanket handler `:413-430` → `Extraction.nothing()`).
- **Whose paper is it: nothing checks.** The prompt asks for `patient_name` and `patient_id`
  (`extract_document.txt:8`); grepping `patient_name|patient_id` across `backend/app` finds **no comparison
  site**. `looks_like_an_identity_card` exists (`backend/app/insurance/insurer.py:52`) and is never called from
  `backend/app/ingestion/`. Worse: `person.birth_year` and `person.sex` read off a lab header are written as
  profile facts (`review.py:1438-1451`) and then drive reference ranges (`reasoning/trends.py:285,302-309`),
  the emergency card (`safety/emergency_card.py:289`) and the screening schedule (`visits/planner.py:351`). A
  wrong person's paper can change the age and sex the app reasons with. Those rows are also collapsed out of
  sight by default on a lab report (`web/src/onboarding/review.ts:489-502`).
- **Duplicates: nothing, of either kind.** No `SELECT … WHERE sha256 = …` anywhere; `Artifact.sha256` is a
  plain non-unique column (`backend/migrations/versions/0003_memory_stores.py:76`). `supersedes_id=None` is
  hard-coded at `review.py:938`, so a re-upload writes a second set of current facts. Demonstrated live: the
  same policy twice, the same panel three times, no warning (capture `32-pa-your-papers`).
- **"Is this a health paper?"** — only the model's own `not_health`, after the bytes are stored and (on the
  Claude path) sent. No blur, resolution, orientation or similarity check; grepped `blur|sharpness|legib`.
  `unknown` produces **no notice at all** (`review.py:156-167` handles `NOT_HEALTH` and
  `UNSUPPORTED_FILE_TYPE`, falls through to `None` for `UNKNOWN`).
- **A multi-plan policy schedule** is merged and unattributed. The prompt defines a single-valued identity
  block (`extract_document.txt:18`), the client takes the first match (`web/src/insurance/model.ts:94-97`,
  `.find`), and the essentials are cut at 12 lines (`backend/app/insurance/policy.py:85-93`). Nothing asks which
  plan is his.
- **Page limits: none.** Grepped `max_page|page_limit`. A PDF is handed whole to the model, base64, in one
  message (`claude_extract.py:212-224`), `MAX_TOKENS = 8192` (`:77`); overrun → `Extraction.nothing()`
  (`:390-395`), i.e. "could not read this page", indistinguishable from a blurry photo. No chunking, no partial
  result. N photos of one document are N unrelated documents (`web/src/capture/batch.ts:101-141`).
- **Intake never asks anything.** Grepped `clarif|question` across `backend/app/ingestion/*.py`: nothing. The
  read-back lets the person retype a number or leave a row out (`web/src/onboarding/review.ts:149-170`) and
  nothing else — not the kind, not the date, not "this isn't my paper".

### 3.3 Memory and context

- A confirmed field becomes a `Fact` with `confidence=1.0` **hard-coded** (`review.py:933`) — every per-field
  confidence the extractor computed, including the deliberate pill-photo cap, is discarded at the boundary.
- `valid_to` is never written by any paper path and `supersedes_id` is always `None`. Facts accumulate as
  parallel "current" rows and nothing picks a winner (`memory/semantic.py:419-470`).
- The window is written and **not read on the Ask path**: `_facts_under` (`backend/app/search/ask.py:533-549`)
  filters only `superseded_at IS NULL` and `!= DISPUTED` — no window, no ordering, no limit.
- `_read_insurance` (`ask_agent.py:827-842`) returns four fields and a 400-character human paraphrase. The
  structured essentials — `coverage_items`, `excludes`, `benefits`, `claim_steps`, each with its printed page
  number (`backend/app/insurance/policy.py:247-258`) — are populated, have an API
  (`channels/api/insurance.py:33-77`) and are **invisible to Ask**. There is no deductible, co-pay or room-rate
  column anywhere (grepped).
- **No cross-source join exists in code**, on either asker. The default rule-based asker does not read insurance
  at all (grepped `insurance|policy|Scope.MONEY` in `search/ask.py`).
- Conversation memory works: `Conversation`/`Turn` rows, text in the object store, six turns verbatim
  (`backend/app/search/conversation.py:58`, `ask_agent.py:923`), folded into a deterministic one-line summary
  after that. But it carries **text, not cites** — the token ids reset per ask (`ask_agent.py:417-429`), so a
  follow-up cannot re-cite what the last turn found.
- **Live bug found:** Ask reads medication lines without `status == ACTIVE` (`search/ask.py:461-467` and
  `ask_agent.py:528-534` filter only `superseded_at`). Every other flow filters on ACTIVE
  (`reasoning/analyst/rule.py:416-427`). **Ask will describe a stopped medicine as current.**

### 3.4 Orchestration

- Nine model call sites, one per task (`backend/app/llm/models.py:40-51`). `CLIP` is **not wired** — only tests
  construct `ClaudeClipMaker` (`backend/app/delivery/feed/clipmaker.py:266`); no setting, no dep, no
  construction in `main.py`.
- Per-task models, `models.py:63-73`: EXTRACT and ASK on `claude-opus-5`; ANALYST, SEARCH, DRAFT, ESTIMATE on
  `claude-sonnet-5`; COMPRESS, CLIP, NARRATE on `claude-haiku-4-5`.
- **No worker, no queue, no scheduler** anywhere (grepped `celery|dramatiq|arq|apscheduler|cron` in
  `pyproject.toml`, `fly.toml`, `render.yaml`). "Background" means in-process `asyncio.create_task`.
  `run_weekly` (`reasoning/analyst/weekly_job.py:57`) is **dead code** — grepped the whole repo; its only hits
  are its own `def` and its own `__all__`. The weekly report never runs unattended.
- **Nothing runs in the background after a paper is confirmed.** `confirm_card`
  (`channels/api/capture.py:380-406`) does the fact writes and returns. The insight is client-driven and
  foreground: the screen issues a fresh `POST …/insight/stream` (`web/src/screens/Insight.tsx:90`); leave the
  screen and the `AbortController` throws the work away. Nothing records that an insight was owed.
- **Timeouts.** ASK has no per-call deadline; `MAX_ROUNDS = 6` (`ask_agent.py:160`) against a 60 s client
  timeout (`backend/app/llm/client.py:27`) is ~360 s worst case, plus `search_online` on a **synchronous client
  with no timeout at all** (`feed/claude_adapters.py:129-132`, SDK default 10 min). SEARCH, COMPRESS, CLIP and
  ESTIMATE have no timeout of any kind.
- **No SSE heartbeat exists.** `backend/app/channels/api/sse_pump.py` is 57 lines with no ping; grepped
  `heartbeat|keep_alive|ping` across `backend/app` — nothing. The client gives up after 180 s of silence
  (`web/src/api/client.ts:143`) on a justification its own docstring gets wrong (`:139-141`, `:431`).
- `review_artifact_stream` (`backend/app/ingestion/review.py:437`) **holds a DB session open across the Opus
  extraction call** — the exact defect `reasoning/analyst/paper.py` was restructured to avoid.

### 3.5 The Home headline rule

`web/src/today/model.ts:356-371`, `homeTopItem`, in priority order:

```
doseDue → allTaken → today's reading → a visit within a week → a reorder → paper → (quiet)
```

The newest paper filed is **last**. Measured: Pa confirmed a blood test and Home still said *"Every tablet for
today is taken."* (`31-pa-home-after-paper`). For a brand-new person with no doses the paper does win

picks the **first** item with `category === "insight"` from `[...top, ...forYou]` — list order, not recency.

## 4. Duplication, wording and spacing

**4.1 The detached full stop, on every accented headline.** `accentLastWord`
(`web/src/today/model.ts:390-400`) pushes punctuation **outside** the accent span (`*taken*.`);
`parseAccentSpans` then makes `.` its own display unit, and `.soft-word { margin-right: 0.27em }`
(`web/src/ui/kit/kit.css:109-112`) puts a word gap after the accent. Rendered: **"is *taken* ."**. Seen on
Welcome ("together . Your"), Home, Add a medicine ("from the *label* ."), and every reading headline.

**4.2 Text duplication.**
- Record hub: title "Your papers" over a list whose second row is also "Your papers".
- Analyst: the headline finding and the "What changed" card state nearly the same sentence (top vs bottom
  blood-pressure number).
- Health: "Your week, looked at closely" + "Nura looked at this on Tuesday 22 September" + the finding + "The
  week of Monday 21 September" — four stacked lines where the blueprint has two.
- Insurance after "Looks right": the propose sheet renders **over** the still-present "Nura has no insurance
  written down for you yet." empty state.
- Onboarding read-back and questions: the status line from the previous card persists — *"Nura will not build
  on that one."* is still on screen on cards 2, 3, 4, 5 and 6 of 6; *"Nura will leave this one out."* likewise

## 7. Part D — the application layer as an agentic system

The owner's question: *"in the Claude app I can load any image, link or file and it handles, contextualises,
remembers, correlates and alerts me — why can't Nura?"* This section answers it against Anthropic's
[Building effective agents](https://www.anthropic.com/engineering/building-effective-agents) and the
[AG-UI protocol](https://github.com/ag-ui-protocol/ag-ui).

### 7.1 Inventory

`grep -rn "messages.create" backend/` returns nine non-test sites, and so does `record_call(`. There is **no
Claude Agent SDK** anywhere (grepped `claude_agent_sdk|ClaudeSDKClient`); every call is the raw `anthropic`

Only four of nine use a prompt file, against `backend/CLAUDE.md`'s own rule.

**Event vocabularies — six, for eight event names, with the serialiser copy-pasted five times.** `_sse()` is
duplicated at `timeline.py:100`, `capture.py:86`, `analyst.py:87`, `feed.py:510`, `safety.py:159`; each emits a
bare `data:` line, no `event:`, no `id:`, no retry, no heartbeat. The six unions are declared at
`web/src/api/types.ts:386, :405, :473, :525, :553, :567`.

| Route | Events |
|---|---|
| `POST …/ask/stream`, `…/turns/stream` | `step{key,label,name}`, `step_label`, `answer_sentence`, `answer`, `refusal` |
| `POST …/find/stream` | `step{key,label}` (key always `"searching"`), `step_label`, `results`, `refusal` |
| `POST …/insights/stream` | `step{key,label,name}`, `report`, `refusal` |
| `POST …/papers/{id}/insight/stream` | `step{key,label}`, `report` (different payload type, same name), `refusal` (phase 3 has no `except Refusal` — a refusal there kills the connection silently) |
| `POST …/photos/stream`, `…/imports/stream` | `step{key,label}`, `card`, `refusal` |
| `POST …/not-feeling-well/stream` | `step`, `card`, `refusal` — and this trace is **replayed after the work finishes** (`safety.py:210-216`), by design and by its own docstring |

That is **four mutually incompatible terminal events for one concept** (`answer`, `results`, `report`, `card`)
and **four payload shapes under the single name `step`**.

**Client.** `web/src/api/client.ts` `apiStream` (`:440`) splits on `\n\n`, takes the first `data:` line, parses
it unguarded (`:510`), intercepts `refusal` (`:511`), and hands **any unknown type straight through** (`:514`)
to an `if/else-if` chain in `web/src/api/nura.ts` with no `else` — unknown events are dropped silently, with no
log. That is the entire forward-compatibility story. Six wrappers (`nura.ts:404, :447, :499, :534, :704, :818,
:1098, :1256`) collapse each vocabulary to callbacks before a screen sees it, and reject with **six different
hand-written strings** for the one condition "the terminal event never came". No screen switches on an event
type. **Defect found in passing:** `paperInsightStream` (`nura.ts:534`) passes the caller's abort signal inside
the `Call` object, which `client.ts` never reads (`Call.signal` is declared at `:52` and read nowhere) — so
leaving the Insight screen does not tear down the connection. `insightsStream` (`:521`) gets it right.

**What a single AG-UI-shaped vocabulary would replace:** six unions, five `_sse` copies, eight event names,
six rejection strings, and the per-screen reducers that fake the lifecycle. AG-UI's ~16 event types cover
lifecycle (`RUN_STARTED`/`RUN_FINISHED`/`RUN_ERROR`, step start/finish), text (`TEXT_MESSAGE_START/CONTENT/END`),
tool calls (`TOOL_CALL_START/ARGS/END/RESULT`), state (`STATE_SNAPSHOT`, `STATE_DELTA`, `MESSAGES_SNAPSHOT`) and
`CUSTOM`/`RAW`, over any transport.

**AG-UI concepts with no equivalent here:**
- **Structured tool calls — absent.** Grepped `tool_call|tool_use|toolCall` across `backend/app/channels`:
  zero. The ask agent runs a real tool loop and the UI is told only *"a thing was read"*, never what, with what
  arguments, or what came back — `ask_agent.py:1316` maps a tool name through `TOOL_STEP_KEYS` (`:183-195`)
  into an opaque localised sentence, and the identity is gone by the time it reaches the wire.
- **`STATE_SNAPSHOT`/`STATE_DELTA` — absent.** No shared agent/UI state object exists.
- **Bidirectional state — absent.** Streams are POST-then-read, one way.
- **Human-in-the-loop interrupt — absent.** The clarifying question is not an interrupt: `ClarifyOut` rides
  inside the **final** `answer` event (`types.ts:306`), the run ends, and the chip tap starts a **whole new
  run** (`Ask.tsx:140`, resolved at `timeline.py:463-475`).
- **Generative UI — absent.** Every payload is a fixed Pydantic model rendered by a hard-coded component.

**What the UI already fakes.** `web/src/health/insights.ts:120-125` invents `start` and `error` actions
client-side because the wire has no `RUN_STARTED`/`RUN_ERROR` — AG-UI's lifecycle, reimplemented in one screen.
Step completion is synthesised by the arrival of the next step (`web/src/capture/batch.ts:117-125`,
`paperTrace.ts:20`). Run status is derived in the kit (`Conversation.tsx:104`, `:154`). The prose step list
(`Conversation.tsx:80`) **is** the tool-call surface, and it is server-rendered localised text
(`delivery/timeline_strings.py:330`), not data the client can reason about.

### 7.4 Verdict on AG-UI

**Adopt the event vocabulary over the existing SSE. Do not adopt the library.**

- Adopting the **vocabulary** is the whole of the win and costs one shared `events.py` plus one shared client
  parser. It collapses six unions into one, gives `RUN_STARTED`/`RUN_ERROR` (today faked in one screen), gives
  a place to put `TOOL_CALL_*` (today thrown away), and makes an unknown event a typed no-op instead of a silent
  drop at `client.ts:514`. It is a protocol, not a framework — nothing about it requires changing the
  orchestrator, which the repo's own modularity rules would forbid anyway.
- Adopting the **library** buys integrations with LangGraph, CrewAI, Mastra and the rest, which this repo does
  not use and whose adoption would violate its "never assume the orchestrator" rule. It also brings a
  dependency into a strict-CSP offline PWA for no benefit the vocabulary alone does not give.
- **Leaving the streams alone is the wrong answer**, because packages 18–22 will each add a seventh, eighth and
  ninth vocabulary on the current pattern.

**I did not verify** the exact AG-UI event names against the specification — the README states "~16 standard
event types" and the categories, and I did not fetch the event schema itself. Any implementation should read

### 7.5 The minimum change that lets Nura accept "any input"

Five pieces, in order. Nothing here removes a safety veto.

1. **One shared context assembly.** Make `current_state` the real choke point its docstring claims, and have
   Ask, the Analyst and intake read it. This is what "contextualises, remembers, correlates" actually means, and
   it removes D-7 and the 13 divergent medicine reads as a side effect. *~16 h.*
2. **Route intake by kind, and let it ask.** A cheap classify call, then a kind-specific prompt and schema, then
   a HITL interrupt for whose-paper, which-plan and is-this-a-duplicate. *~20 h on top of D-2 and D-4.*
3. **One event vocabulary, AG-UI-shaped, with real tool-call events.** A shared `events.py`, one client parser,
   and the ask loop emitting `TOOL_CALL_START/RESULT` instead of a prose sentence. This is what makes the
   interrupt in (2) expressible at all. *~20 h.*
4. **Replace the prose-shaping half of the gate with a model judge, keep the vetoes as code.** The vetoes stay
   exactly as they are; the judge decides whether a sentence is a conclusion or a quotation — the thing
   `narrate.py:119` cannot do. *~16 h, plus (5).*
5. **An evaluation harness.** Plug `paper_accuracy.py` into the real extractor, and add a graded set for Ask
   (question, record state, acceptable answer) so (4) can be proven rather than argued. *~16 h.*

**Cost in model calls per paper.** Today: **1** (extract), plus **1** more if the person opens the insight
screen and stays on it. Under (2): **1** cheap classify (Haiku) + **1** kind-specific extract (Opus) + **1**
validation pass on identity and low-confidence fields (Sonnet) = **3**, of which only one is Opus-sized — so
roughly the same Opus spend, plus two small calls. A duplicate stops at the digest check and costs **0**, which
on a re-photographed folder is a net saving against today's one-Opus-call-per-upload. **I did not measure
token counts**; these are call counts, not cost.
